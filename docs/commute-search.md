# Main-map commute search

Find homes by commute sits below the map search. Visitors pick a university, area or landmark from the suggestions, or enter a full UK postcode. They then choose a maximum journey time (5–180 minutes), travel mode (public transport, walking or cycling), arrival date and time. Times are London local time. The initial date is the next weekday and the initial arrival time is 09:00. TfL supports searches up to 28 days ahead here.

The search uses TfL Journey Planner to route from each published development to the coordinates of the chosen place or the postcode centre. It uses `journey.duration` for the full itinerary. Public transport requests include tube, bus, DLR, Overground, Elizabeth line, national rail, tram and walking. Walking and cycling modes reject routes of the wrong type. Unsupported or failed journeys appear separately as unavailable.

The browser sends published IDs in batches of five, with two batches at a time and a checked-home progress count. Search cancellation aborts pending client requests and ignores late responses. Failed whole batches do not apply a misleading incomplete filter. Completed search results filter the map and listings, intersecting with the existing property, featured and favourites filters. The limit can be adjusted against completed results without another route lookup. Matching pins have journey-time tooltips and listing cards have time badges. The map frames the destination and matching homes; it does not use a guessed travel radius.

`POST /api/commute` is public, origin checked, bounded to a 6 KB payload and at most five published IDs. Place IDs resolve against the map’s university, area and landmark catalogue. Postcode lookup uses Postcodes.io and route requests use the TfL API. Destination and successful route caches are bounded and in memory only, with one-hour and ten-minute lifetimes respectively. Failed journeys are retried. Netlify’s existing IP rate limit still applies. Journeys depend on TfL coverage and current schedules, so visitors should allow extra time for delays and use the timings as guidance.

The desktop header has equal outer grid columns so the title is centred across the navigation bar. The title is hidden at mobile widths. Intermediate tablet widths use a separate controls row to prevent overlap. Icon-only desktop controls retain accessible names; mobile inputs use 16 px type to avoid Safari focus zoom.

Verification covers destination search and validation, exact TfL mode names, total duration and modal filtering, weekend/London date handling, cache invalidation/coalescing, unconfirmed routes, payload/origin checks and matching thresholds. The local browser test selected Canary Wharf from the suggestions and returned TfL public transport results.
